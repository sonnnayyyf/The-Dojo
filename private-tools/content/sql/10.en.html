Lesson 10 — LEFT JOIN & NULL

The JOIN from Lesson 9 (also called INNER JOIN) keeps only rows that match in both tables. But many important questions live in the non-matches: "which customer has never ordered?", "which product has never sold?". An INNER JOIN hides exactly the rows you're looking for.

LEFT JOIN solves this: it keeps all rows from the left table, and for rows with no match on the right it fills in NULL (the "empty" value). So a customer with no orders still appears — with NULL in the order columns.

Customer Phạm Thị D has no orders, and several products never sold — perfect data to practise LEFT JOIN and handling NULL with IS NULL and COALESCE.

1. LEFT JOIN — keep every left row

Change JOIN to LEFT JOIN: every customer appears, even those with no orders (the order columns will be NULL).

SELECT c.name AS customer, o.id AS order_id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
ORDER BY c.id, o.id;
Exercise 1. Join customers to orders with LEFT JOIN, show c.name AS customer and o.id AS order_id (every customer, including those with no orders), sorted by c.id, o.id.

2. IS NULL — find the non-matches

You can't compare NULL with =. You must use IS NULL (or IS NOT NULL). The combination LEFT JOIN + WHERE ... IS NULL is the classic way to find "the ones with no match".

SELECT c.name AS customer
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;
Exercise 2. Find customers who have never ordered: LEFT JOIN customers to orders, filter o.id IS NULL, show c.name AS customer, sorted by c.id.
Exercise 3. Find products that have never sold: LEFT JOIN products to order_items, filter oi.id IS NULL, show p.name AS product, sorted by p.id.

3. Counting including zero

A subtle difference: COUNT(*) counts rows, but COUNT(column) skips NULL. So COUNT(o.id) over a LEFT JOIN correctly gives 0 for a customer with no orders.

SELECT c.name AS customer, COUNT(o.id) AS order_count
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.id
ORDER BY c.id;
Exercise 4. Count the number of orders per customer, including 0: LEFT JOIN customers to orders, group by c.id, show c.name AS customer and COUNT(o.id) AS order_count, sorted by c.id.
Exercise 5. Count the number of line items per customer, including 0: LEFT JOIN customers → orders → order_items, group by c.id, show c.name AS customer and COUNT(oi.id) AS line_count, sorted by c.id.

4. COALESCE — replace NULL with something else

SUM over an empty group returns NULL, not 0. COALESCE(x, 0) means "if x is NULL, use 0 instead". Perfect for money reports.

SELECT c.name AS customer,
       COALESCE(SUM(p.price * oi.qty), 0) AS total_spent
FROM customers c
LEFT JOIN orders o      ON o.customer_id = c.id
LEFT JOIN order_items oi ON oi.order_id = o.id
LEFT JOIN products p     ON oi.product_id = p.id
GROUP BY c.id
ORDER BY c.id;
Exercise 6. Total spend per customer, with 0 for non-buyers: use the LEFT JOIN chain shown, show c.name AS customer and COALESCE(SUM(p.price * oi.qty), 0) AS total_spent, group by c.id, sorted by c.id.
Exercise 7. Total quantity sold per product, with 0 for unsold: LEFT JOIN products to order_items, show p.name AS product and COALESCE(SUM(oi.qty), 0) AS total_qty, group by p.id, sorted by p.id.

5. IS NOT NULL and HAVING

Conversely, IS NOT NULL keeps rows that did match. And you can filter for "empty" groups with HAVING COUNT(...) = 0.

Exercise 8. Count how many line items each product appears in, including 0: LEFT JOIN products to order_items, show p.name AS product and COUNT(oi.id) AS times_ordered, group by p.id, sorted by times_ordered descending then p.id.
Exercise 9. Find unsold products using HAVING: LEFT JOIN products to order_items, group by p.id, keep groups with COUNT(oi.id) = 0, show p.name AS product, sorted by p.id.
Exercise 10. List the names of customers who have at least one order (using IS NOT NULL): LEFT JOIN customers to orders, filter o.id IS NOT NULL, show DISTINCT c.name AS customer, sorted by c.id.
