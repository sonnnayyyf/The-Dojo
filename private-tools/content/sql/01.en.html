Lesson 1 — SELECT: your first queries

A database is simply a set of tables — exactly like an Excel spreadsheet: each table has columns and rows. SQL is the language you use to ask questions of those tables and get answers back. Nothing to install: below is a real database for a small shop, running right in your browser.

This lesson covers just one statement — SELECT — but it's the one you'll use most in your whole career. It reads data: which columns, from which table. We won't filter rows yet (Lesson 2) or sort them (Lesson 3) — we'll just focus on pulling out the columns you want.

Take it slow. Every "▶ Try it" box is a real editor: type a query, run it, see the result, and get graded instantly. Getting it wrong is fine — just try again.

2. The shape of a query

A basic SELECT has two parts: choose the columns, and name the table.

SELECT name, price
FROM products;

Read it as: "SELECT the columns name, price FROM the products table". The ; ends the statement. SQL is not case-sensitive, but a good habit is to write keywords in UPPERCASE (SELECT, FROM) so they stand out.

3. SELECT * — every column

The * means "all columns". Handy for a quick peek at what a table contains.

SELECT * FROM products;
Exercise 1. Show all columns of every product in the products table.

4. Choosing just the columns you need

In practice you rarely want everything. Name exactly the columns you want, separated by commas.

SELECT name, price FROM products;

5. Column order is up to you

Columns appear in the order you write them — they don't have to follow the table's order.

SELECT price, name FROM products;

6. Working with the other tables

SELECT works on any table — just change the name after FROM.

SELECT * FROM customers;

7. DISTINCT — remove duplicates

Many products share a category. If you only want to know "what kinds of items does the shop sell?", add DISTINCT right after SELECT so each value appears only once.

SELECT DISTINCT category FROM products;
