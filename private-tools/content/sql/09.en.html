Lesson 9 — JOIN: connecting tables

Real data doesn't sit in one table — it's split apart to avoid repetition. The orders table only stores a customer_id, not the customer's name; to answer "who placed this order?" you have to join orders to customers. This is the skill that separates people who know basic SQL from people who really use it.

JOIN stitches rows from two tables together on a matching condition — usually a foreign key matching a primary key. For example orders.customer_id = customers.id.

Our shop has four linked tables, shown below. Once you understand these links, you can answer almost any question.

1. INNER JOIN — match rows together

Syntax: name the first table in FROM, the second in JOIN, and state the match condition in ON. Use short table aliases (o, c) and refer to columns as o.column.

SELECT o.id AS order_id, c.name AS customer
FROM orders o
JOIN customers c ON o.customer_id = c.id
ORDER BY o.id;

Each order is matched to its customer. Because name exists in both tables, you must write c.name.

Exercise 2. As above but add o.order_date in the middle: order_id, order_date, customer. Sort by o.id.

2. Joining a detail table to its catalog

order_items only has a product_id — join to products to get the name and price.

SELECT oi.order_id, p.name AS product, oi.qty
FROM order_items oi
JOIN products p ON oi.product_id = p.id
ORDER BY oi.id;
Exercise 3. Join order_items to products: show oi.order_id, p.name AS product, oi.qty, sorted by oi.id.

3. Calculating after a join

Once joined, you can use columns from both tables in one expression — e.g. line total = price × quantity.

SELECT p.name AS product, oi.qty, p.price,
       p.price * oi.qty AS line_total
FROM order_items oi
JOIN products p ON oi.product_id = p.id
ORDER BY oi.id;
Exercise 4. Join order_items to products; show p.name AS product, oi.qty, p.price, and p.price * oi.qty AS line_total. Sort by oi.id.

4. Join with a filter (WHERE)

WHERE works as usual after a join — and you can filter on a column from any table.

Exercise 5. Items in order 4: join order_items to products, filter oi.order_id = 4, show p.name AS product, oi.qty, sorted by oi.id.
Exercise 6. Orders from customers in Hà Nội: join orders to customers, filter c.city = 'Hà Nội', show o.id AS order_id, c.name AS customer, sorted by o.id.

5. Join then group (JOIN + GROUP BY)

The real power: join tables, then aggregate. For example, total quantity each customer bought.

SELECT o.customer_id, SUM(oi.qty) AS total_qty
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
GROUP BY o.customer_id
ORDER BY o.customer_id;
Exercise 7. Total quantity each customer bought: join orders to order_items, group by o.customer_id, show o.customer_id and SUM(oi.qty) AS total_qty, sorted by o.customer_id.
Exercise 8. Revenue per category: join order_items to products, group by p.category, show p.category and SUM(p.price * oi.qty) AS revenue, sorted by p.category.

6. Joining three tables or more

Need both the customer name and the product name for each line? Just keep chaining tables — one JOIN … ON … each.

SELECT c.name AS customer, p.name AS product, oi.qty
FROM order_items oi
JOIN orders o    ON oi.order_id = o.id
JOIN customers c ON o.customer_id = c.id
JOIN products p  ON oi.product_id = p.id
ORDER BY oi.id;
Exercise 9. For each line item, show c.name AS customer, p.name AS product, oi.qty (join all four tables as above), sorted by oi.id.
Exercise 10. Number of orders per customer (with names): join orders to customers, group by c.id, show c.name AS customer and COUNT(*) AS order_count, sorted by c.id.

7. Putting it all together

Exercise 11. 🔥 Stretch. Total spend per customer. Join orders → order_items → products → customers, group by c.id, show c.name AS customer and SUM(p.price * oi.qty) AS total_spent, sorted by total_spent descending.
