Lesson 14 — CREATE TABLE & data types

Until now the tables products, customers… already existed. But when you build a new app, you design the tables: pick a table name, declare the columns and their data types. That's the job of CREATE TABLE.

The three most basic data types in SQLite: INTEGER (whole numbers), TEXT (strings), and REAL (decimals). You can also add constraints: PRIMARY KEY (a unique identifier), NOT NULL (a value is required), DEFAULT (a fallback value).

As in the last lesson, each exercise has you create a table, add data, then SELECT to see the result. Each run uses a fresh database, so create tables freely.

1. CREATE TABLE — make a table

Declare the table name, then in parentheses a list of column_name type, separated by commas.

CREATE TABLE suppliers (id INTEGER, name TEXT);
INSERT INTO suppliers VALUES (1, 'Công ty A');

SELECT * FROM suppliers;
Exercise 1. Create the table suppliers (id INTEGER, name TEXT), add the row (1, 'Công ty A'), then the SELECT below shows it.

2. Data types: INTEGER, TEXT, REAL

REAL is for numbers with a decimal part (e.g. weight, ratio).

CREATE TABLE items (id INTEGER, name TEXT, weight REAL);
INSERT INTO items VALUES (1, 'Gạo', 5.5);

SELECT name, weight FROM items;
Exercise 2. Create items (id INTEGER, name TEXT, weight REAL), add (1, 'Gạo', 5.5).
Exercise 3. Create sales (id INTEGER, price REAL, qty INTEGER), add (1, 10.5, 3), then compute price * qty AS total.

3. PRIMARY KEY

PRIMARY KEY marks the column that uniquely identifies each row (like the id column in the tables you've been using).

CREATE TABLE tags (id INTEGER PRIMARY KEY, label TEXT);
INSERT INTO tags VALUES (1, 'new'), (2, 'sale');

SELECT COUNT(*) AS n FROM tags;
Exercise 4. Create tags (id INTEGER PRIMARY KEY, label TEXT), add two rows (1, 'new'), (2, 'sale').
Exercise 5. Create colors (id INTEGER, name TEXT), add three rows (1, 'red'), (2, 'green'), (3, 'blue'), then SELECT name ... ORDER BY id.

4. NOT NULL and DEFAULT

NOT NULL requires a value. DEFAULT provides a fallback value when you don't name that column during INSERT.

CREATE TABLE tickets (id INTEGER, status TEXT DEFAULT 'open');
INSERT INTO tickets (id) VALUES (1);

SELECT status FROM tickets WHERE id = 1;
Exercise 6. Create staff (id INTEGER PRIMARY KEY, name TEXT NOT NULL), add (1, 'An').
Exercise 7. Create tickets (id INTEGER, status TEXT DEFAULT 'open'), add only the id: INSERT INTO tickets (id) VALUES (1). The status column defaults to 'open'.
Exercise 8. Create members (id INTEGER PRIMARY KEY, name TEXT NOT NULL, points INTEGER DEFAULT 0), add only id and name (1, 'Minh'). The points column defaults to 0.

5. Building a table from existing data

CREATE TABLE … AS SELECT … makes a new table and fills it with a query's result. INSERT INTO … SELECT … copies data into an existing table.

CREATE TABLE cheap AS
  SELECT name, price FROM products WHERE price < 15000;

SELECT COUNT(*) AS n FROM cheap;
Exercise 9. Create a table cheap holding name, price of products priced below 15000: CREATE TABLE cheap AS SELECT name, price FROM products WHERE price < 15000.
Exercise 10. Create an empty table drinks (name TEXT, price INTEGER), then copy all 'Đồ uống' rows into it with INSERT INTO drinks SELECT name, price FROM products WHERE category = 'Đồ uống'.
