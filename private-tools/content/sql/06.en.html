Lesson 6 — GROUP BY & HAVING: grouped reports

In Lesson 5 you computed one number for the whole table: total stock, average price… But real reports always ask per group: "revenue per category?", "orders per customer?", "how many sold per product?". You don't want to run 4 queries for 4 categories — you want one query that returns one row per group.

That's GROUP BY. It splits rows into groups by a column's value, then applies an aggregate function to each group. The result: one row per group, with the number you computed.

And when you want to filter the groups themselves (e.g. "only categories with more than 2 products"), you use HAVING — like WHERE, but for the results after grouping.

1. GROUP BY — one row per group

Golden rule: a column after GROUP BY may appear in SELECT; every other column must be inside an aggregate function.

SELECT category, COUNT(*) AS n
FROM products
GROUP BY category
ORDER BY category;

The result: one row per category with its product count. (Add ORDER BY so the order is always stable.)

Exercise 1. Count the number of products in each category: show category and COUNT(*) AS n, grouped by category, sorted by category.

2. SUM and AVG per group

Swap COUNT for SUM or AVG to get a total/average for each group.

SELECT category, SUM(stock) AS total_stock
FROM products
GROUP BY category
ORDER BY category;
Exercise 2. Compute the total stock per category: category, SUM(stock) AS total_stock, grouped by category, sorted by category.
Exercise 3. Compute the average price per category, rounded: category, ROUND(AVG(price)) AS avg_price, grouped by category, sorted by category.

3. Several numbers per group

You can place multiple aggregates at once — each group gets a "summary row".

Exercise 4. For each category, show MIN(price) AS cheapest and MAX(price) AS most_expensive. Grouped by category, sorted by category.

4. Sorting by the computed number

Very common: group, then sort by the aggregate itself to find the "biggest" group.

SELECT category, COUNT(*) AS n
FROM products
GROUP BY category
ORDER BY n DESC, category;
Exercise 5. Count products per category, sorted by count descending; break ties by category. (Hint: ORDER BY n DESC, category.)

5. HAVING — filter the groups

WHERE filters rows before grouping; HAVING filters groups after grouping. So a condition using an aggregate (like COUNT(*) > 2) must go in HAVING.

SELECT category, COUNT(*) AS n
FROM products
GROUP BY category
HAVING COUNT(*) > 2
ORDER BY category;
Exercise 6. Only categories with more than 2 products: show category, COUNT(*) AS n. Use HAVING COUNT(*) > 2, sorted by category.
Exercise 7. Only categories with total stock of 300 or more: show category, SUM(stock) AS total_stock. Use HAVING SUM(stock) >= 300, sorted by category.
