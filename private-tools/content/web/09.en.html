Lesson 9 — Mini project: a static library site

Time to put it all together. Over the last eight lessons you learned to structure pages with HTML, style them with CSS, lay them out with flexbox and grid, and add motion. Now you'll build a real, multi-page website: the City Library — a home page plus subpages for Books, About and Contact, tied together with a navigation bar. This is exactly how small real sites are built.

First you'll meet two things every real page needs but our snippets skipped: the full HTML document skeleton (the <!doctype>, <head> and <body> wrapper, with a <title> and a linked stylesheet), and links between pages — the relative URLs like books.html that turn separate files into one connected site. You'll also use <div> and <span>, the generic containers you group and style with classes.

Then you'll build the site piece by piece — a nav bar, a header, a book grid, subpages — each graded as you go, finishing with a full styled home page. Let's ship a website.

1. The full document skeleton

Every real HTML file starts with a fixed skeleton. <!doctype html> tells the browser this is modern HTML. Inside <html> there are two parts: the <head> holds information about the page — the character set, the <title> (shown in the browser tab), and links to CSS files — while the <body> holds everything you actually see.

On a real site each page (index.html, books.html…) is its own file linking to a shared style.css via <link rel="stylesheet" href="style.css"> in the head. In these exercises the CSS box is that shared stylesheet.

2. Linking pages together

A multi-page site is just several HTML files that link to each other. A link to another page in the same folder uses a relative URL — just the file name: <a href="books.html">Books</a>. Put these links in a <nav> and every page can reach every other. (In the sandbox the links won't navigate, but on a deployed site they jump between pages.)
