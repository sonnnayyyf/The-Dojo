Lesson 14 — Events & interactivity

Everything so far ran once, the moment the page loaded. But real apps wait for the user and react: a button waits to be clicked, a box waits for you to type, a menu waits to be opened. That waiting-and-reacting is powered by events — signals the browser fires when something happens ("this was clicked", "a key was pressed"). Handle events and your page becomes an app.

The tool is element.addEventListener("click", handler): you tell an element which event to listen for and give it a function to run each time that event happens. Inside the handler you do the work — change text, update a count, read what the user typed. Reading input is just input.value.

These exercises are graded by simulating the user — the grader clicks your button or types into your box, then checks that your page reacted correctly. So you get to build genuinely interactive widgets: counters, greeters, toggles, a mini to-do. Let's make the page respond.

1. Reacting to a click

addEventListener("click", fn) runs fn every time the element is clicked. The function holds whatever should happen.

let btn = document.querySelector("#btn");
btn.addEventListener("click", function () {
  document.querySelector("#out").textContent = "Clicked!";
});

3. Reading what the user typed

An input's current text is input.value. Read it inside a click handler to react to whatever the user entered.

let name = document.querySelector("#name").value;
document.querySelector("#out").textContent = "Hi " + name;
Exercise 7. ✍️ Your turn. Greet the user. On click of #btn, read #name's value and set #out to Hi + that value. (The grader types Mai, so it should read Hi Mai.)

4. Toggling with classList

classList.toggle("name") adds a class if it's missing and removes it if it's there — perfect for on/off buttons like "dark mode" or "liked".
