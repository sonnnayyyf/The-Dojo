Lesson 3 — HTML structure: lists, tables, forms & semantic layout

So far your pages have been a flat stack of headings and paragraphs. Real websites are more organised: menus are lists, data sits in tables, sign-up boxes are forms, and the whole page is divided into meaningful regions like a header, a main area and a footer. HTML has dedicated elements for every one of these, and using the right element makes your page easier to style, easier to read for screen-readers, and easier for search engines to understand.

The thread running through this lesson is nesting — putting elements inside other elements. A list is a container (<ul>) holding items (<li>); a table is rows (<tr>) holding cells (<td>); a form is a box (<form>) holding inputs. Once you see HTML as boxes-inside-boxes, structuring a whole page becomes natural.

You'll build every one of these live: a navigation list, a price table, a working sign-up form, and finally a full page laid out with semantic regions. Edit, Run, watch it take shape, and get graded as you go.

1. Lists

Use an unordered list <ul> for items where order doesn't matter (bullets), and an ordered list <ol> when it does (numbered steps). Both hold list items, <li> — one per entry.

2. Tables

Tables show data in rows and columns. A <table> holds rows <tr>; each row holds cells. Use <th> for header cells (bold) and <td> for data cells.

3. Forms

Forms collect input from the user. A <form> wraps controls like <input> (a text box) and <button>. An input's type attribute picks the kind (text, email, password…), and placeholder shows grey hint text. A <label> names a field so it's clear and accessible.

4. Semantic layout

You could build a whole page out of plain boxes, but HTML gives semantic elements that name a page's regions: <header> (top bar / title), <nav> (navigation links), <main> (the primary content), <section> (a grouped chunk) and <footer> (bottom bar). They render the same as a plain box but tell browsers, screen-readers and search engines what each region means.
