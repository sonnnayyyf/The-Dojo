Bài 15 — Form, kiểm tra dữ liệu & fetch

Form là cách web thu thập thông tin thật — đăng nhập, đăng ký, tìm kiếm, thanh toán. Bạn đã biết dựng HTML của một form; giờ bạn sẽ làm nó hoạt động bằng JavaScript: bắt sự kiện submit, đọc những gì được gõ, và kiểm tra (validate) nó (email đã điền chưa? mật khẩu đủ dài chưa?) trước khi làm gì. Kiểm tra dữ liệu tốt là thứ tách một món đồ chơi khỏi một sản phẩm thật.

Bạn cũng sẽ gặp hai thứ cho phép một trang nói chuyện với thế giới bên ngoài. JSON là định dạng văn bản phổ quát cho dữ liệu — mọi API trên đời đều nói nó — và JavaScript có thể biến văn bản JSON thành object (JSON.parse) và ngược lại (JSON.stringify). Và fetch là hàm yêu cầu dữ liệu từ một máy chủ mà không tải lại trang, kỹ thuật đứng sau tìm kiếm trực tiếp, bảng tin và các nút "tải thêm".

Bạn sẽ gắn dây các handler submit, chặn form rỗng bằng thông báo lỗi rõ ràng, và biến JSON thành một danh sách được hiển thị — đúng những gì một ứng dụng thật làm với dữ liệu nó fetch về. Xử lý dữ liệu thật nào.

1. Xử lý submit form

Khi một form được submit, mặc định nó cố tải lại trang. Trong một ứng dụng JavaScript, bạn chặn điều đó bằng event.preventDefault(), rồi tự xử lý mọi thứ trong một listener submit.

let form = document.querySelector("form");
form.addEventListener("submit", function (e) {
  e.preventDefault();               // chặn tải lại
  document.querySelector("#out").textContent = "Submitted!";
});
Bài tập 1. ✍️ Đến lượt bạn. Bắt submit. Thêm một listener submit cho form gọi e.preventDefault() và gán #out thành Sent. (Bộ chấm submit form.)
Bài tập 2. Lệnh nào chặn một form tải lại trang khi submit?
  1. e.stop()
  2. e.preventDefault()
  3. form.reload()
  4. return true

2. Đọc các ô & kiểm tra

Bên trong handler submit, đọc .value của từng ô và kiểm tra nó. Nếu có gì sai, hiện một thông báo và dừng; nếu không thì tiếp tục. Đây là validation.

Bài tập 3. ✍️ Đến lượt bạn. Bắt buộc có tên. Khi submit, nếu value của #name rỗng, gán #err thành Required; ngược lại gán OK. (Bộ chấm thử cả ô rỗng và ô đã điền.)
Bài tập 4. ✍️ Đến lượt bạn. Kiểm tra độ dài. Khi submit, nếu value của #pw có ít hơn 6 ký tự (.length < 6), gán #err thành Too short; ngược lại Good.
Bài tập 5. ✍️ Đến lượt bạn. Kiểm tra email trông hợp lệ. Khi submit, nếu value của #email không chứa @ (dùng .includes("@")), gán #err thành Invalid; ngược lại Valid.

3. JSON — ngôn ngữ của dữ liệu

JSON là văn bản trông như object và mảng JavaScript. JSON.parse(text) biến một chuỗi JSON thành một object thật để bạn đọc; JSON.stringify(obj) làm ngược lại. Đây là cách dữ liệu di chuyển giữa các ứng dụng và máy chủ.

let text = '{"name":"Mai","age":20}';
let user = JSON.parse(text);
console.log(user.name);            // Mai
console.log(JSON.stringify(user)); // trở lại thành text
Bài tập 6. ✍️ Đến lượt bạn. Parse JSON. Biến text là một chuỗi JSON. JSON.parse nó thành user, rồi console.log(user.city) (phải in Hanoi).
Bài tập 7. ✍️ Đến lượt bạn. Tạo JSON. Tạo let book = { title: "Dune" };, rồi console.log(JSON.stringify(book)) (phải in {"title":"Dune"}).
Bài tập 8. ✍️ Đến lượt bạn. Hiển thị dữ liệu kiểu-fetch. text là một mảng JSON các object sách. Parse nó, rồi lặp để đổ đầy #list với một <li> mỗi tựa. (Ba mục sẽ hiện ra.)

4. fetch — dữ liệu từ máy chủ

Để tải dữ liệu từ một API mà không tải lại, bạn dùng fetch(url). Nó trả về một promise, nên bạn nối .then() để xử lý phản hồi khi nó về — trước tiên biến nó thành JSON, rồi dùng nó:

fetch("https://api.example.com/books")
  .then(response => response.json())   // parse phần thân JSON
  .then(data => {
    console.log(data);                 // giờ dùng dữ liệu
  });

Dữ liệu bạn nhận về là JSON — đúng thứ bạn vừa luyện parse ở trên. (Các bài tập này không gọi API thật — trên trang đã triển khai bạn sẽ trỏ fetch tới URL thật — nhưng hình dạng luôn là như vậy.)

Bài tập 9. Sau fetch(url), bạn gọi gì để biến phần thân phản hồi thành một object dùng được?
  1. chỉ response.text
  2. response.json()
  3. JSON.fetch()
  4. response.reload()
Bài tập 10. ✍️ Đến lượt bạn. Xử lý một phản hồi API. Giả sử data là thứ một fetch trả về. Đọc data.title và đặt nó vào #out (phải đọc Dune).

5. Ghép lại

Bài tập 11. ✍️ Đến lượt bạn. Một form thêm-mục hoạt động. Khi submit, nếu #item rỗng hiện #err = Required; ngược lại nối value thành một <li> trong #list và xóa #err. Nhớ e.preventDefault().
Bài tập 12. 🔥 Nâng cao — ✍️ đến lượt bạn. Một bộ kiểm tra đăng ký. Khi submit: nếu #user rỗng → #err = Name required; nếu không mà độ dài #pw < 6 → #err = Password too short; nếu không → #err = Welcome. (Bộ chấm thử cả ba trường hợp.)
