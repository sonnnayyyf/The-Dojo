Lesson 6 — The for loop & range

A computer isn't smarter than you — it's just fast and never gets bored. The real power of programming comes from telling the machine to do one thing over and over, thousands of times, without tiring or making mistakes. The tool for that is the loop, and it's the biggest leap in your programming thinking so far.

Imagine greeting 100 students. Writing 100 print lines is tedious and error-prone, and if the list changes you'd fix each line by hand. There's a golden rule: DRY — Don't Repeat Yourself. When you notice you're about to copy–paste the same code several times, you almost certainly want a loop instead.

This lesson goes slowly: we'll dissect each part of the for loop, watch the machine run it step by step, and only then practice. Nail this and the later lessons (nested lists, dictionaries, reading files) get much easier.

1. The problem: repeating by hand

Suppose we have three names and want to greet each one:

# the manual way: repetitive, error-prone, hard to change
print("Hello An")
print("Hello Binh")
print("Hello Chi")

It works — but ask yourself: what if there were 100 names? What if the list is read from a file and you don't even know how many names there'll be when you write the code? We need a way to tell the machine: "do this for each name, however many there are." That's exactly what the for loop is for.

2. Anatomy of a for loop

The same task, written with a loop:

ten = ["An", "Binh", "Chi"]
for t in ten:
    print("Hello", t)

One body line replaces three repeated lines. Read its four parts carefully:

  • for — the opening keyword, telling the machine "get ready to loop".
  • t — the loop variable, which you name. On each pass, the machine puts one element of the list into it.
  • in ten — the collection to walk through: a list, a string, or a range (section 4).
  • : and the indented block below — the loop body, the code repeated each pass.

Just like if, indentation decides which lines are inside the loop. Only indented lines repeat; a non-indented line runs once, after the loop finishes.

for t in ["An", "Binh"]:
    print("Inside:", t)       # indented -> runs each pass
    print("  (still inside)")
print("All done!")            # not indented -> runs once, at the end

3. How the machine runs a loop

Under the hood, the machine repeats exactly three steps: (1) ask "is there an element I haven't taken yet?"; (2) if yes, take the next one into the loop variable and run the body; (3) go back to step 1. When there are no elements left, the loop stops.

The best way to understand a loop is to make a trace table of the loop variable across passes. For for t in ["An", "Binh", "Chi"]:

Passt becomesPrints
1"An"Hello An
2"Binh"Hello Binh
3"Chi"Hello Chi
—(none left)loop stops

This "running the code in your head" skill — tracing how variables change each pass — is something every good programmer does. For every loop you meet, try drawing a table like this.

4. range() — generate a sequence of numbers to loop over

Often you don't have a list — you just want to loop a fixed number of times, e.g. "do it 10 times" or "count from 1 to 100". range produces exactly that sequence. There are three forms:

Written asProducesMeaning
range(5)0, 1, 2, 3, 4from 0, stop before 5
range(1, 6)1, 2, 3, 4, 5from 1, stop before 6
range(0, 10, 2)0, 2, 4, 6, 8step of 2

Why stop before the last number instead of at it? It's a Python convention (like slicing [a:b]). It means range(len(my_list)) gives exactly the valid indexes 0..n-1.

for i in range(5):
    print(i, end=" ")   # 0 1 2 3 4
print()
for i in range(1, 6):
    print(i, end=" ")   # 1 2 3 4 5

You can also walk a list by index by combining range and len — handy when you need each element's position:

ten = ["An", "Binh", "Chi"]
for i in range(len(ten)):
    print(i, ten[i])    # 0 An / 1 Binh / 2 Chi

5. The "accumulator" pattern — the most important shape

So many loop problems follow the same shape: you want to fold many values into one result (a sum, a count, a joined string, the largest value…). The recipe is always three parts:

  1. Initialize a result variable before the loop (often 0, "", or []).
  2. Update it on each pass.
  3. Use the result after the loop.
nums = [4, 8, 2, 6]
tong = 0            # 1) initialize
for n in nums:
    tong += n       # 2) update each pass
print(tong)         # 3) use the result -> 20

Trace tong across passes: 0 → 4 → 12 → 14 → 20. If you forget the tong = 0 line, the machine errors with "tong is not defined" on the first pass — a very common mistake.

6. Filter & count: put an if inside the loop

Combine two skills you already have — loops (this lesson) and conditions (lessons 3–4) — into one of the most common code patterns: walk through and only handle elements that match a condition.

nums = [1, 2, 3, 4, 5, 6]
so_chan = 0
for n in nums:
    if n % 2 == 0:      # the if is INSIDE the for (indented twice)
        so_chan += 1
print(so_chan)          # 3

Notice the two indent levels: for at level 0, the for body indented once, the if body indented twice. When reading deeply-indented code, always ask "which block does this line belong to?".

7. Building a new list with a loop

A variant of the accumulator: start with an empty list and append as you go. This is how you "transform" one list into another — extremely common.

squares = []
for i in range(1, 6):
    squares.append(i ** 2)
print(squares)      # [1, 4, 9, 16, 25]

8. Common confusions

  • Forgetting to initialize the accumulator before the loop → "not defined" error.
  • Putting the "use the result" line INSIDE the loop (wrong indent) → it runs every pass instead of once at the end.
  • Thinking range(1, 5) goes to 5 — it actually stops at 4. To reach 5 use range(1, 6).
  • Changing a list while looping over it (adding/removing) → causes unpredictable bugs; avoid it for now.
