Lesson 15 — Errors: try / except

Up to now, when something went wrong — dividing by zero, turning "abc" into a number, reading a key that isn't there — your program simply crashed with a red error message and stopped dead. That's fine while learning, but a real program can't fall over every time a user types something odd. It needs to expect trouble and handle it calmly.

Python's tool for this is try / except: you put the risky code in a try block, and if it raises an error, Python jumps to the except block instead of crashing. Your program keeps running and can give a sensible response — a default value, a friendly message, a skipped item.

This is the difference between a fragile script and software people can actually use. Handling bad input gracefully is one of the clearest marks of a real developer.

1. What an error looks like

Certain operations fail at runtime and raise a named exception. A few you'll meet constantly:

CodeExceptionWhy
int("abc")ValueErrortext isn't a number
10 / 0ZeroDivisionErrorcan't divide by zero
d["missing"]KeyErrorno such key in the dict
items[99]IndexErrorposition is past the end

Without handling, any of these stops the whole program.

2. try / except

Wrap the risky line in try. If it fails, the except block runs instead.

def safe_int(s):
    try:
        return int(s)        # risky: might fail
    except ValueError:
        return 0             # runs only if int() failed

print(safe_int("42"))    # 42
print(safe_int("abc"))   # 0  — no crash
Exercise 1. Define safe_int that returns int(s), or 0 if s can't be converted. So safe_int("42") is 42 and safe_int("abc") is 0.
Exercise 2. Define safe_divide that returns a / b, or 0 if b is zero (catch ZeroDivisionError). So safe_divide(10, 2) is 5.0 and safe_divide(5, 0) is 0.

3. Catching the right error

Name the exception you expect after except. This keeps you from accidentally hiding bugs you didn't mean to catch. Reading a missing dictionary key raises KeyError; an out-of-range list index raises IndexError.

def safe_get(d, key):
    try:
        return d[key]
    except KeyError:
        return "missing"

person = {"name": "Anna"}
print(safe_get(person, "name"))    # Anna
print(safe_get(person, "email"))   # missing
Exercise 3. Define safe_get that returns d[key], or "missing" if the key isn't there. So for {"name": "Anna"}, safe_get(d, "name") is "Anna" and safe_get(d, "email") is "missing".
Exercise 4. Define get_item that returns items[i], or None if the index is out of range (catch IndexError). So get_item([10, 20], 0) is 10 and get_item([10, 20], 5) is None.
Exercise 5. Define to_float that returns float(s), or None if it can't convert. So to_float("3.5") is 3.5 and to_float("x") is None.

4. Handling bad items in a loop

A very common real task: process a list where some entries are bad. Wrap the risky bit in try and just skip (or default) the failures — the loop keeps going.

values = ["1", "2", "x", "3"]
total = 0
for v in values:
    try:
        total += int(v)
    except ValueError:
        pass                 # ignore the bad one
print(total)   # 6
Exercise 6. Define sum_numbers that adds up the values in a list that can be turned into int, skipping the rest. So sum_numbers(["1", "2", "x", "3"]) is 6.
Exercise 7. Define count_valid that returns how many strings in values can be converted to int. So count_valid(["1", "2", "x", "3"]) is 3.
Exercise 8. Define percent that returns round(part / whole * 100), or 0 if whole is zero. So percent(1, 4) is 25 and percent(1, 0) is 0.
Exercise 9. Define clean_ints that returns a list of the int values from values, dropping any that don't convert. So clean_ints(["10", "x", "20"]) is [10, 20].
🔥 Stretch (robust average). Define safe_average that averages only the values in values that convert to a number, and returns 0 if none do. So safe_average(["2", "x", "4"]) is 3.0 and safe_average(["a"]) is 0.
Recap of lesson 15: risky operations raise named exceptions (ValueError, ZeroDivisionError, KeyError, IndexError) that crash the program if unhandled · put risky code in try and the recovery in except · name the specific exception you expect so you don't hide other bugs · in a loop, try/except lets you skip or default bad items and keep going.
