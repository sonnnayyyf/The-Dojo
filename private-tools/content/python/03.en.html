Lesson 3 — Conditions: if / elif / else

So far our programs run straight through, top to bottom. But real software has to make decisions: old enough → let them in, wrong password → show an error, order over 500k → apply a discount. This lesson teaches the computer to choose a path based on a condition.

1. Comparisons — the basis of every decision

A comparison always produces a bool: True or False.

print(7 > 3)      # True
print(7 < 3)      # False
print(5 == 5)     # True  — EQUAL? (two equals signs)
print(5 != 4)     # True  — NOT equal?
print(5 >= 5)     # True  — greater or equal
print(5 <= 4)     # False — less or equal

Very important: = is assignment (put a value into a variable), while == is comparison (ask whether two things are equal). Mixing them up is a classic beginner bug.

Exercise 1. Given a = 7 and b = 10, create a_is_smaller = whether a is less than b (result is True/False).

2. if — do something WHEN a condition is true

Structure: the keyword if, a condition, a colon :, then an indented block below.

temperature = 39
if temperature > 37.5:
    print("You have a fever!")   # this line is INDENTED -> belongs to if
print("Check complete")          # NOT indented -> always runs

Indentation decides everything in Python. Lines indented to the same level form a block that runs together. Convention: indent by 4 spaces. Wrong indentation → an error, or the wrong behavior.

Exercise 2. alert starts as False. If temperature is greater than 37.5, set alert to True.

3. else — otherwise, do this

age = 15
if age >= 18:
    print("Come in")
else:
    print("Too young")     # runs when the if condition is FALSE
Exercise 3. Given score = 4, create result = "Pass" if score >= 5, otherwise "Fail".

4. elif — many branches

When there are more than two cases, use elif (short for "else if"). Python checks top to bottom and runs the first TRUE branch, skipping the rest.

score = 7
if score >= 8:
    grade = "Excellent"
elif score >= 6.5:
    grade = "Good"
elif score >= 5:
    grade = "Average"
else:
    grade = "Weak"
print(grade)      # Kha
Exercise 4. Given score = 7, create grade by scale: >= 8 → "Excellent"; >= 6.5 → "Good"; >= 5 → "Average"; otherwise → "Weak".

5. Branch ORDER matters a lot

Because Python stops at the first true branch, wrong ordering gives wrong answers. If you put >= 5 before >= 8, then a score of 9 would be labeled "Average" because it matches >= 5 first. Always put the strictest (narrowest) condition on top.

Exercise 5. Given age = 20, create group: < 13 → "child"; < 20 → "teen"; otherwise → "adult".
Exercise 6. Given number = -4, create sign: "positive" if number > 0; "negative" if number < 0; "zero" if it is 0.

6. Use remainder % to test even/odd

A number is even when divided by 2 with remainder 0. So n % 2 == 0 means "n is even".

n = 10
if n % 2 == 0:
    print("even")
else:
    print("odd")
Exercise 7. Given n = 7, create kind = "even" if n is even, otherwise "odd" (hint: use % 2).
Exercise 8. Given hours = 14 (hour of day, 0–23), create part_of_day: < 12 → "morning"; < 18 → "afternoon"; otherwise → "evening".

7. Comparing strings & membership (in)

Conditions aren't just for numbers. You can compare strings with ==, and test whether a value is in a group with in (lists [...] are covered in depth in lesson 5).

role = "admin"
if role == "admin":
    print("Full access")

day = "T7"
if day in ["T7", "CN"]:
    print("Weekend")
Exercise 9. Given day = "CN", create is_weekend = True if day is "T7" or "CN" (hint: use day in ["T7", "CN"]).

8. Common mistakes

  • Forgetting the colon : after the condition → syntax error.
  • Missing or uneven indentation → IndentationError.
  • Using = instead of == in a condition → error.
  • Wrong elif order → the program runs but gives wrong answers (the hardest bug to spot).
Recap of lesson 3: comparisons give True/False (== != < > <= >=) · if condition: + indented block runs when true · else for the remaining case · elif for many branches, runs the first true one · branch order matters · string comparison & in · = assigns ≠ == compares.
