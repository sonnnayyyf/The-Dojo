Project A — Text Analyser

Feed your program a block of text and have it report interesting facts: total words, unique words, the most common word, the average word length. A tiny version of the tools real writers and data folk use.

Data model: the text is a string; text.split() gives the words; a dictionary counts them.

Build steps:

  1. Store a paragraph of a few sentences in a variable text. (Later, swap to text = input("Paste text: ").)
  2. Lowercase it first with text.lower() so "The" and "the" count as the same word.
  3. Split into words with .split() and print "Total words: N" using len.
  4. Use a set to print how many unique words there are.
  5. Build a word → count dictionary with the counting pattern (counts[w] = counts.get(w, 0) + 1).
  6. Loop the dictionary to find and print the most common word (track the biggest count so far).
  7. Print the average word length, rounded (sum of len(w) ÷ number of words).
  8. Wrap the whole thing in a function analyse(text) that returns a report dictionary, then print each line of the report neatly.

Make it yours (pick a few): strip punctuation with .replace(",", "").replace(".", "") before counting · show the top 3 words with their counts · count sentences by splitting on "." · find the longest and shortest word · ignore common "stop words" like "the", "a", "is" using a list · draw a tiny bar chart with "#" * count next to each top word · keep asking for text in a loop until the user types "quit".

Warm-up A. Define average_word_length that returns the average length of the words in text, rounded to 1 decimal. So average_word_length("a bb ccc") is 2.0.

Project B — Expense Tracker

Track spending: each expense is a record with a description, an amount, and a category. The program adds expenses, lists them, totals them, and breaks the total down by category.

Data model: a list of dictionaries like {"desc": "Lunch", "amount": 50, "category": "food"}.

Build steps:

  1. Start a list of 4–5 expense dictionaries, each with desc, amount and category.
  2. Loop and print each as "Lunch — 50 (food)" using an f-string.
  3. Print the grand total of all amounts (a loop, or sum).
  4. Write total_by_category(records, cat) (your warm-up) and reuse it.
  5. Get the set of categories, then print the total for each category.
  6. Find and print the single biggest expense (its description and amount).
  7. Print each category's share as a percentage of the grand total, rounded.
  8. Add a while True menu (1 add · 2 list · 3 totals · 4 quit) reading input(); on "4", break.
  9. Make "add" read a description, an amount (with int(input())) and a category, then append a new dict — guard a bad amount with try/except so it never crashes.

Make it yours (pick a few): sort expenses biggest → smallest · set a budget and warn when a category goes over it · show the average expense · let the user filter by a category they type · count how many expenses are in each category · build one formatted report string you could save · add a date field and show the newest first.

Warm-up B. Define total_by_category that sums the amount of the records whose category matches cat. For the records below, total_by_category(records, "food") is 130.

Project C — Quiz Game

A quiz that asks questions, checks answers, keeps score, and reports how the player did. Great practice with loops, conditions and dictionaries.

Data model: a list of question dictionaries like {"q": "Capital of Vietnam?", "a": "Hanoi"}.

Build steps:

  1. Store 3–5 question dictionaries (each {"q": ..., "a": ...}) in a list.
  2. Loop with enumerate and print each as "Q1: ...".
  3. For each question, read the player's answer with input() and compare it to the correct one, counting a score.
  4. Make checking fair by comparing answer.strip().lower() on both sides.
  5. Print the final score like "You got 2 / 3".
  6. Print a message by score band — e.g. all correct → "Perfect!", at least half → "Not bad", else → "Keep practising".
  7. Keep a list of the questions the player got wrong and show them (with the right answers) at the end.
  8. Turn one question into multiple choice: show options a/b/c and accept the letter.

Make it yours (pick a few): shuffle the questions with the random module · add categories or difficulty levels and let the player choose · reveal the correct answer after a wrong guess · keep a high score across rounds · let the player add their own questions with input() · give a point bonus for a streak of correct answers.

Warm-up C. Define score_quiz that takes the player's answers and the correct answers (two equal-length lists) and returns how many match by position. So score_quiz(["a", "b", "c"], ["a", "x", "c"]) is 2.
